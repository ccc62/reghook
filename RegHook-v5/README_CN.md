# RegHook v5（ARM64 / ptrace 硬件执行断点）

> 实验版本。v4 已在用户设备上报告过一次成功寄存器写回和游戏内效果，但 v5 的修改尚未在真机验证。请先在自己有权调试的测试进程上测试，错误的寄存器修改仍可能导致目标进程异常。

## 相比 v4 的改动

1. **区分单步停止类型**：不再把所有 `SIGTRAP` 都当成单步完成；正常情况下要求 `si_code == TRAP_TRACE`。
2. **处理单步被其他信号打断**：尝试重新启用断点后再传递该信号，避免 `stepping` 状态一直残留。
3. **避免单步失败后立即反复命中**：若 `PTRACE_SINGLESTEP` 本身失败，不在同一 PC 立即重新启用该线程的断点，以避免陷入反复陷阱；该线程本次运行会暂时停止监控，退出时仍尝试恢复原硬件调试状态。
4. **更清晰的统计**：分别统计识别到的硬件断点事件、寄存器写回成功/失败、单步失败、断点启用相关失败、继续执行失败、恢复失败和分离失败。
5. **改进线程清理诊断**：恢复或分离失败时显示错误码；未确认线程停止时不会假装已成功恢复。
6. **明确区分安装与运行**：分别输出成功安装断点的线程数、成功恢复运行的线程数。

## 仍然存在的限制

- 不自动跟踪启动后新建的线程。
- 线程可能在枚举期间退出或新建；附加/等待失败仍可能发生。
- 不同 Android 厂商内核对 ptrace、硬件断点和单步信号的行为可能不同。
- 统计值只能反映程序观察到的事件；不能保证所有目标代码路径都被命中。
- v5 仅做静态检查与宿主机编译冒烟检查；需要用 GitHub Actions 构建真正的 Android ARM64 版本，并在设备上验证。

## 构建

在 GitHub 仓库根目录放置本目录与 `.github/workflows/build.yml`，然后在 Actions 中手动运行 **Build RegHook v5 ARM64**。工作流使用 Android NDK 交叉编译 `aarch64-linux-android24`，并上传二进制和源码 ZIP。

## 使用建议

- 首先在自建、可重复的 ARM64 测试程序上验证断点安装、重复命中、退出清理。
- 先保存 v4 可用二进制与日志；v5 尚未通过真机回归前，不要覆盖 v4。
- 如果出现卡死、异常退出或断点不再命中，保存完整日志与最终统计，先停止测试，不要在重要进程上反复试。
