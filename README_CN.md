# RegHook v6（ARM64 / ptrace 硬件执行断点）

> 实验版本。v4 曾在用户设备上报告过一次成功寄存器写回与游戏内效果；v5 的核心断点逻辑也由用户报告正常工作。v6 主要优化输入交互和输出，不代表已经在真机完成回归测试。请先在自己有权调试的测试进程中验证，错误的寄存器修改仍可能导致目标进程异常。

## v6 改动

1. **错误输入原地重试**：PID、断点地址、寄存器、修改值输入不合法时，只重新询问当前字段，不退出程序重来。
2. **支持返回上一步**：地址输入 `q` 返回 PID；寄存器输入 `q` 返回地址；修改值输入 `q` 返回寄存器；PID 输入 `q` 退出。
3. **简洁启动输出**：默认不逐条输出每个线程的硬件断点槽位，减少大量线程时的刷屏。
4. **可选详细诊断**：配置完成后输入 `y` 可查看逐线程附加和断点安装诊断；默认直接按简洁模式运行。
5. **命中实时刷新**：每次识别到断点并成功写回寄存器后，立即更新当前统计行（使用回车覆盖同一行，避免每次命中都换行）。
6. **增加安装阶段汇总**：最终统计增加线程附加/停止失败次数和断点安装失败线程数。
7. **尽量保持 v5 核心处理不变**：命中后修改寄存器、单步越过并重新启用断点的主要流程未作设计性改动。

## 使用说明

- PID 输入十进制数字。
- 断点地址和修改值输入十六进制，可带 `0x` 前缀。
- 断点地址必须非零且 4 字节对齐。
- 寄存器输入 `X0` 至 `X30`，也可只输入数字，例如 `X8` 或 `8`。
- 统计中的“寄存器写回成功”表示调试器成功写回目标线程寄存器上下文，不保证目标程序后续不会再次覆盖相关数据。
- 运行期间按 `Ctrl+C` 停止，程序会尝试恢复原硬件断点状态并分离线程。

## 已知限制

- 不自动跟踪启动后新建的线程。
- 线程可能在枚举期间退出或新建；附加/等待失败仍可能发生。
- Android 厂商内核对 ptrace、硬件断点和单步信号的行为可能不同。
- 逐次刷新只影响统计行输出；它不是对目标进程行为的额外保证。
- 此环境无法完成 Android NDK 真正的 ARM64 交叉编译或设备回归测试；请用下方 GitHub Actions 工作流构建，并保留 v4/v5 可用版本作为备份。

## 构建

将 `RegHook-v6/` 和 `.github/workflows/build.yml` 放在 GitHub 仓库根目录，在 Actions 中运行 **Build RegHook v6 ARM64**。工作流使用 Android NDK 交叉编译 `aarch64-linux-android24`，并上传二进制和源码 ZIP。
