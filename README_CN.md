# RegHook v3（ARM64）

这是一个**实验性原型**，尝试通过 `ptrace` 的 `NT_ARM_HW_BREAK` regset 设置 ARM64 硬件执行断点，并在目标线程命中时写回 X0–X30 中指定寄存器。

## 与 v2 的主要区别

- 不再混用 `perf_event_open`、异步 `SIGTRAP` 和 `ptrace` 单步处理。
- 使用 `PTRACE_GETREGSET/SETREGSET` 访问 `NT_ARM_HW_BREAK`，读取内核报告的断点槽位，并选择一个空闲槽位。
- 记录并在退出时尝试恢复原硬件断点状态。
- 对命中后的指令使用单步越过，再重新启用该线程的断点。
- 解析输入时去除常见方向控制字符，并显示配置确认。

## 构建

通过 GitHub Actions 的 `Build Android ARM64` 工作流构建，产物为 `reghook-arm64`。

## 使用限制与重要警告

- 尚未在真实 Android 设备上验证；编译成功不代表目标内核支持该 regset 或该行为可靠。
- 仅在自己拥有/有权调试的测试进程上使用。`ptrace` 会暂停线程；错误断点地址、异常处理差异或目标程序自身的调试状态都可能导致目标异常退出。
- 本版针对现存线程设置断点；新建线程不会自动加入。
- 如果内核返回不支持 `NT_ARM_HW_BREAK`、没有空闲槽位或权限不足，程序会报告失败并尝试清理，而不是保证继续运行。
- 某些内核/设备对 `NT_ARM_HW_BREAK` 的结构长度、控制位或信号代码处理可能有差异。请先在简单的自有 ARM64 测试程序中验证，并保留日志。
- 在目标程序崩溃后，`ECHILD` 仅表示当前没有可等待的跟踪线程，不能单独证明根因。
