# RegHook v6.2（ARM64 / ptrace 硬件执行断点）

> 实验版本。用户此前报告 v4 在其设备上成功修改寄存器并观察到游戏内效果；v6.2 的改动尚未在真实 Android ARM64 设备上完成回归测试。请先在自己有权调试的测试进程中验证。错误的寄存器修改仍可能导致目标进程异常。

## v6.2 改动

1. **错误输入原地重试**：PID、断点地址、寄存器、修改值输入不合法时，只重新询问当前字段。
2. **返回上一步**：地址输入 `q` 返回 PID；寄存器输入 `q` 返回地址；修改值输入 `q` 返回寄存器；PID 输入 `q` 退出。
3. **简洁启动输出**：默认不逐条打印每个线程的硬件断点槽位；可选详细诊断。
4. **实时命中统计**：每次成功写回寄存器时更新同一统计行。
5. **超长输入保护**：清空输入行剩余字符，避免把残留内容误读成下一个参数。
6. **断点地址映射检查**：若能读取 `/proc/<PID>/maps`，要求地址位于目标进程的可执行映射中；无法读取 maps 时提示并跳过此项检查。
7. **异常命中处理**：无法读取寄存器时停止监控并进入清理；PC 不匹配时保留并转发 `SIGTRAP`，不再一概抑制。
8. **断点关闭失败保护**：关闭断点失败时不继续单步，停止监控并进入清理。
9. **单步中断保护**：单步被其他停止打断时先检查 PC；若仍在目标地址或无法读取 PC，不盲目重新启用断点，以降低反复触发风险。该线程可能因此停止后续监控。
10. **线程恢复失败保护**：启动阶段或运行阶段恢复线程失败时停止监控并执行清理，避免继续循环等待。
11. **清理和统计**：增加寄存器上下文读取失败、清理时无法确认线程停止、发现/附加/恢复运行线程数等统计。

## 使用说明

- PID 输入十进制数字。
- 断点地址和修改值输入十六进制，可带 `0x` 前缀。
- 断点地址必须非零且 4 字节对齐；若目标进程的 maps 可读取，还必须位于可执行映射。
- 寄存器输入 `X0` 至 `X30`，也可只输入数字，例如 `X8` 或 `8`。
- 除 PID 外，在各输入项输入 `q` 可返回上一步；PID 输入 `q` 退出。
- 统计中的“寄存器写回成功”表示调试器成功写回目标线程寄存器上下文，不保证目标程序后续不会再次覆盖相关数据。
- 运行期间按 `Ctrl+C` 停止，程序会尝试恢复原硬件断点状态并分离线程。

## 已知限制与注意事项

- 不自动跟踪启动后新建的线程。
- 线程可能在枚举期间退出或新建；附加/等待失败仍可能发生。
- 若清理时无法确认线程处于 ptrace-stop，程序会报告严重警告；此时不能保证成功恢复该线程的硬件状态或分离关系，应检查目标进程状态。
- 某些异常路径会主动停止对单个线程的监控，以优先避免反复触发；这意味着该线程之后的命中可能不再被记录。
- Android 厂商内核对 ptrace、硬件断点和单步信号的行为可能不同。
- 本环境只做了基础 C 语法检查和主机端输入烟雾测试；没有完成 Android NDK 真正的 ARM64 交叉编译或设备回归测试。请通过 GitHub Actions 构建，并保留已知可用的 v4/v5 作为备份。

## 构建

把 `reg_hook.c`、`README_CN.md` 和 `.github/workflows/build.yml` 放在 GitHub 仓库根目录。进入 Actions 运行 **Build RegHook v6.2 ARM64**。工作流使用 Android NDK 编译 `aarch64-linux-android24`，并上传二进制和源码 ZIP。
